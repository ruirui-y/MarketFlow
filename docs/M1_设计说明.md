# M1 设计说明：二进制读取与分钟窗口聚合

> 这份文档只写「为什么这么做」和「实测到什么」。流程图和结构图放在 `drawio/` 里，两边不重复。

**术语**：tick = 一条成交记录；bar = 一分钟 K 线；窗口 = 一分钟；界线 = 收到过的最新成交时间往回退 3 秒。

---

## 一、M1 要解决什么

把一份定长的逐笔成交二进制文件，按分钟聚合成 K 线，并且要做到两件事：

1. 结果必须和暴力重算完全一致，不能有一根 K 线对不上；
2. 跑得足够快，快到能证明聚合本身不是瓶颈。

---

## 二、四条定死的规则

| 规则 | 选择 | 为什么 |
|---|---|---|
| 窗口边界 | 时间戳除以一分钟向下取整 | 保证窗口不重叠、可重复计算，同一份数据永远得到同一批 K 线 |
| 迟到的成交记录 | 那一分钟还没交出去就照常并入；已经交出去就丢弃并计数 | 真实行情一定有乱序。允许乱序的价值在于「不错过」，而丢弃必须计数，不能悄悄丢 |
| 空窗口 | 没有成交的分钟不生成 K 线 | 用前收盘价填一根假 K 线，图看起来连续，但那个价格从来没有成交过，属于伪造数据 |
| 价格类型 | `int64` 存「分」，不用 double | 成交额是价格乘数量再累加，double 累加会积累误差，还会让「相等」变得不可判断 |

---

## 三、界线怎么工作

```text
界线 = 收到过的最新成交时间 - 3 秒

                  界线
                   │
    ──────┬────────┼───────────┬─────▶ 时间
          │        │           │
      窗口 A      窗口 B      窗口 C
     已交出去      还开着      还开着
    (迟到则丢弃)  (照常并入)
```

判断条件是「窗口结束时刻 ≤ 界线」。窗口一旦交出去，之后来的、属于那一分钟的成交记录一律丢弃，并计数。

注意比的是**结束时刻**，不是起点。窗口 [10:30, 10:31) 要等到最新数据跑到 10:31:03 才关。

**为什么用最小堆，而不是每来一条成交记录就扫一遍所有开着的分钟**

- 开着的分钟数随标的数增长。2000 万条 × 50 个开着的分钟 ≈ 10 亿次比较，直接拖死；
- 只有「结束时刻最早的那个」才可能被关掉，看堆顶就够，代价是 O(log n)。

**为什么先做全局界线，不做每个标的各一条**

- 全局界线取的是所有标的里最大的时间戳，它比单个标的自己的界线更靠前，**关得更早**；
- 后果是快的标的会把慢的标的的分钟提前关掉，慢标的的迟到数据被静默丢弃 —— 这是 M1 现在**已知的缺陷**，不是设计取舍；
- 每个标的各一条界线放到 M1.1 修。

---

## 四、正确性怎么证明

用两套完全独立的写法算同一批数据：

| 实现 | 做法 |
|---|---|
| `BarAggregator` | 界线 + 最小堆 + 到点交出去 |
| 测试里的暴力重算 | 不设界线、不关分钟，所有成交记录直接塞进 `std::map` |

200 万条成交记录（20 标的 × 60 分钟），逐根 K 线比对 `open` / `high` / `low` / `close` / `volume` / `amount` 六个字段，**0 处偏差**。

另外单独覆盖两个用例：那一分钟交出去之后的迟到记录被拒绝且计数为 1；跨整分钟的成交被正确切成两根 K 线。

## 五、实测数据

2000 万条，50 标的 × 240 分钟，回放三次：

| 指标 | 值 |
|---|---|
| 耗时 | 0.321 / 0.311 / 0.312 秒 |
| 吞吐 | 约 6400 万条/s |
| 单条 | 16 ns |
| K 线根数 | 12000 |
| 迟到丢弃 | 0 |

**这份数据必须连着边界一起说**：610MB 文件 0.31 秒读完，等于 2GB/s，那是页缓存命中下的内存带宽，不是磁盘摄入能力。冷读没有测，所以这个数字只能用来说明「聚合不是瓶颈」，不能当成产品指标。

## 六、已知不足

1. 没有做重复数据去重。`Tick.reserved` 这个字段就是留给它的，等接入真实数据源再补。
2. 只有全局界线。快的标的会连累慢的标的，导致慢标的的成交记录被误丢（见第三节）。
3. 单线程。是否要并发，等冷读基线出来再定，不提前优化。
4. 冷读、异步 IO、真实逐笔数据导入都还没接。
